Neural Network Libraries

Why I built this

Neural Network 1

I wanted to understand how neural networks work from first principles. I decided (foolishly so) to make my own neural network library so I could implement forward and back propagation by hand as well as all other functions needed to implement a neural network. I did not use any generative AI for this project. All programming, debugging and design was done by me.

Neural Network 2

My second neural network was a do-over of the whole project. I thought the programming could be improved (from the lessons I learnt in my university programming class) and the whole architecture could be modified so that I could implement a few ideas I had that at the time seemed unique.

How I built it

Neural Network 1

The library was built around a central Neural_Network class, which provided the core interface for creating, training, and modifying neural network architectures. The framework included a broad set of built-in features such as:

  • Dynamic Layer Creation and Removal
  • Dynamic Node Creation and Removal
  • Forward Propagation and Backpropagation
  • Custom Activation Functions and Softmax Support Per Layer
  • Discrete Number Processing Functionality
  • Binary Serialization and Deserialization (.ppm image support)
  • Text-Based Save and Load Features
  • Network Visualization and Print Utilities

Beyond the core framework, I developed several experimental tools focused on neural architecture optimization and automated testing.

One tool was made to evaluate permutations of activation functions across nodes and layers, allowing different activation functions to be benchmarked against a given architecture and dataset.

I also created an automated architecture generation system that began with a minimal network structure and iteratively modified hidden layers and activation functions to minimize cost while working within fixed training and testing dataset constraints.

Additional tooling included:

  • Training and testing dataset generation from arbitrary mathematical functions
  • 2D binary map classification systems for coordinate-based learning problems
  • Automated network experimentation and evaluation utilities

Neural Network 2

After developing a strong foundation in neural network design through my first library, I began building a more advanced framework focused on experimentation with custom neural network architectures and non-standard learning approaches.

The primary goal of this second library was to provide significantly greater control over individual neurons and network connectivity. Unlike my original implementation, where activation functions were applied at the layer level, this framework allowed each node to define its own activation function and connection topology independently.

The architecture was designed to support network experimentation, including weighted and unweighted residual learning, inter-network communication, variable activation functions, and custom cost functions assigned at the individual node level. One area of interest was exploring neuron-like behavior by constraining nodes toward target equilibrium states and introducing controlled disturbances during learning. While still an ongoing area of research, the framework was built to support these forms of experimentation directly.

The library ultimately evolved into a highly modular research-oriented neural network framework with the following functionality:

  • RNN and LSTM functionality
  • Dynamic layer creation and removal
  • Dynamic node creation and removal
  • Forward propagation and backpropagation
  • Custom activation functions and Softmax support for individual nodes
  • Weighted and unweighted residual learning within and between networks
  • Independent/disconnected network structures for experimental memory retention systems
  • Text-based save and load functionality
  • Network visualization and debugging utilities

What I learned

Through the process of designing neural networks and experimenting with different architectures and training configurations, I realized that my primary interest lies not in using pre-existing models, but in building them — and in creating the tools that make such systems possible. This insight made it clear that my long-term direction should focus on developing machine-learning infrastructure, both software and hardware, rather than solely applying existing models.

Constructing these networks also taught me several foundational concepts, most notably the vanishing gradient problem. I independently discovered this issue while training a network that used sigmoid activation functions and initialized weights and biases in the range of −5 to 5. The gradients rapidly diminished, causing many parameters to stop updating altogether. I spent hours inspecting individual neuron values and manually backpropagating computations to verify correctness. Only later did I encounter an article describing the vanishing gradient problem, confirming the phenomenon I had already diagnosed and resolved on my own.

These implementations also strengthened my ability to debug neural networks. After many hours examining failing models, I developed an intuition for the patterns and failure modes that commonly arise when a network behaves unexpectedly. Below is a list of the most frequent issues I encountered.

  • vanishing or exploding gradients
  • weight and bias symmetry
  • parameters becoming stuck or non-responsive
  • uneven or unstable parameter distributions
  • misaligned activation function choices for the task
  • activation functions that suppress or destroy useful signal
