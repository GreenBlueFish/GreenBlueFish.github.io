STM32 Nucleo

Plant Project

View on GitHub ↗

About the Project

For one of my courses in 1A, my teammate and I were tasked with building anything we wanted using an STM32 Nucleo board. There were only a few requirements: we had to solve some kind of problem, use two boards and get them talking to each other, and display something to the user. My partner and I both had a habit of killing houseplants, so naturally, we decided to build an automatic plant monitor.

I was somewhat familiar with microcontrollers at this point, so I implemented all the circuitry and code myself while my partner handled documentation and meetings. The basic layout of the project is shown in the schematic below. Fair warning: there are transistor symbols in there that you should just ignore. At the time, I didn't actually understand how transistors worked and assumed they were perfect digital switches, so my plan was to power each sensor individually by selecting it over the bus line, the idea being that each sensor would only turn on when needed, to save power, since I originally (and incorrectly) thought powering all the sensors at once would draw too much current. Turns out I was wrong once I actually measured it, so I ended up wiring all the sensors up directly instead.

The idea was that 5 sensors would keep track of the plant's health, with that data sent to the user via a 4-digit display. The traffic light indicated overall plant health, the rotary encoder (a potentiometer) and button let the user cycle through different sensor readings, and the RGB LED showed which sensor was currently selected. And yes, I did include a flame sensor, it came bundled in a sensor pack I ordered online, and I thought it would be funny to wire in. If the plant catches fire, the traffic light turns red; in hindsight, maybe an actual alarm would have been the smarter call. Below is a photo of the board with the sensors and interface, minus the 4-digit display.

We weren't allowed to use any libraries except for communication between the boards, so I had to implement the 4-digit display myself, from scratch. Below is a photo of the display alongside the sensors and interface. I never planned on sharing these photos, which is why this one doesn't show the display very well.

To pull this off, I used 4 shift registers to drive each of the 4 seven-segment displays. It took a while to get right, but I got there eventually, the video below shows it counting. I muted the video since I originally recorded it for a friend who'd given me the shift registers and walked me through how to use one.

To see the full documentation my partner and I put together, you can find it here.

About the Project

More about the project can be found here. To give a quick summary: I built a 4-motor drone from scratch, using an ESP32 WROOM board to control it. The ESP32 used PWM to control the ESCs, which in turn controlled the motors. I integrated a gyroscope chip to sense direction and tilt, and I flew the drone using a PS3 controller connected to the ESP32 over Bluetooth.

IC Programmer

About the Project

A friend had ordered too many LH5164A-10L SRAM 64Kbit memory chips and handed me a couple to play around with. I wanted to see how the read/write process actually worked at the hardware level, so I used my Arduino Due to read and write data to one of the chips. The project itself was fairly simple: writing involved sending an 8-bit memory address and 8-bit data to the chip and asserting the write-enable line, while reading meant sending an 8-bit address and reading back the 8-bit data line. I confirmed everything worked by sweeping the entire address space and reading back every value, writing to a handful of specific addresses, then reading again, everything matched, so the read/write logic was solid.
