Drone Design

From-scratch hardware and software implementation of a drone (quadcopter).

Motivation

Why I built this

For my grade 12 tech class I had to spend the entire semester on one project, I thought it would be fun to make a drone. To challange myself I decided to design all hardware and implement all software from scratch. Below is a video of the drone flying. I didn't implement a stabilization algorithm thus why the drone is unstable.

Approach

How I built it

The drone was made up of 4 motors controlled by 4 electric speed controllers (ESCs) which connected to an ESP32 (WROOM) microcontroller which was the brain of the dron. The ESC was pwm controlled and was powered by a custom made power distribution board that hooked up to a fuse, then the lithium ion battery. There was also a gyroscopic sensor that hooked up to the ESP32. The drone connected wirelessly via bluetooth to a PS3 controller (the code to do that was done through an open source library).

I designed all the system control code in C++. I have since lost the code for this project sadly. That being said I do remember the basic structure of the code. There was a main class for ESC control with 4 objects, each controlling one ESC. I had another class that dealt with gyroscopic data and would automatically calculate roll and pitch; a class that dealt with controller input and output (I would shake the controller depending on the total power to the motors, the roll, and the pitch); and a class that delt with safety funcitions, such as when I walked away too far and the controller disconnected it would shut off all motors. Or if the drone's angle changed too quickly.

Reflection

What I learned

One of the most important things building this drone taught me was to always think about safety features from the begining. Origionally I did not have any saftey features, no power cut off, no throttle acceleration control, and no control to cut power if the drone started to tilt. Obviously this was an issue and the first couple times I learnt exactly why I should consider saftey from the very begining. For the record, no one was ever hurt and no property external to the drone was damaged. That being said I did shatter a drone blade againt a locker, damage my microcontroller pins, and damaged the drone body. After these experiences I spent a couple days writing only safety features. This resulted in a power shutoff button, excessive tilt shut off, excessive tilt accleration shut off, throttle control, lost connectivity to controller shut off, sudden change in accleration shut off (if the drone hits something), and lost connectivity to either the ESCs or gyroscope shut off. After I wrote those features no other incidents happened.
